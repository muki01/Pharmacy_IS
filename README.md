# Информационна система за аптека

Курсов проект по дисциплина „Информационни системи“ — задание № 4
Тракийски университет – Стара Загора, Стопански факултет

Настолно приложение за управление на аптека: каталог на лекарствените
продукти, складови наличности по партиди, продажби, доставки, бракуване,
предупреждения и справки.

---

## Бърз старт

```bash
dotnet build                              # компилиране на решението
dotnet test                               # изпълнение на 55-те теста
dotnet run --project src/PharmacyIS.UI    # стартиране на приложението
```

При първо стартиране приложението създава базата от данни, зарежда
номенклатурите и каталога и генерира демонстрационна история от доставки и
продажби за последните три месеца. Подготовката отнема около 15 секунди.

## Основни проектни решения

**Наличността се води по партиди, а не по продукти.** Един и същ продукт
постъпва на партиди с различни срокове на годност и различни доставни цени.
Количеството на продукта е сума от количествата на неговите партиди.

**Изписване по правилото FEFO** (First Expired, First Out). При продажба
първо се изчерпва партидата с най-близък срок на годност. Партиди с изтекъл
срок не участват в продажби.

**Неотрицателна наличност на ниво база от данни.** Намаляването използва
условна заявка `WHERE BatchId = @id AND Quantity + @delta >= 0` и проверява
броя на засегнатите редове. При едновременна работа на две каси операцията
се отменя вместо да създаде отрицателна наличност.

**Складов журнал само за добавяне.** Всяко изменение на наличността създава
запис със знак. Меню „Администрация → Контрол на наличностите“ сравнява
количествата по партидите със сумата от движенията.

**Независимост от СУБД.** Слоят за достъп до данни работи с абстрактните
класове на `System.Data.Common`. Смяната на SQLite с MySQL изисква промяна
само на конфигурационния файл.

**Един прозорец.** Работните страници се сменят в обща работна област, а не
се отварят като отделни прозорци. Навигацията е в странична лента, а личните
действия — смяна на паролата и излизане от профила — са в менюто на
потребителя в горния десен ъгъл. Излизането от профила връща екрана за вход,
без да затваря приложението; затварянето става само от системния бутон.

**Ролята определя какво се вижда.** Освен видимостта на разделите в
навигацията от ролята зависят стойностните колони и обобщения, бутоните за
поддържане на каталога, съдържанието на регистъра на продажбите и темите на
вграденото ръководство.

**Търсене от начало на дума, независимо от регистъра.** „ана“ намира
„Аналгин“, но не и „Панадол“; търси се във всяка дума от наименованието.
Вградената функция за малки букви на SQLite обхваща само латиницата, затова
приложението регистрира собствена, която работи и с кирилица.

**Валута.** Системата работи в евро. Знакът е изнесен в константата
`Money.Currency` в областния модел и не се повтаря в кода на екраните.

## Конфигурация

Файлът `src/PharmacyIS.UI/appsettings.json`:

```json
{
  "Database": {
    "Provider": "Sqlite",
    "ConnectionString": "Data Source=pharmacy.db",
    "AutoCreateDatabase": true,
    "GenerateDemoData": true
  }
}
```

### Преминаване към MySQL

1. Създайте база на сървъра:

```sql
CREATE DATABASE pharmacy_is CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. Изпълнете `db/schema_mysql.sql`.
3. Променете конфигурацията:

```json
{
  "Database": {
    "Provider": "MySql",
    "ConnectionString": "Server=localhost;Port=3306;Database=pharmacy_is;User Id=root;Password=;CharSet=utf8mb4;",
    "AutoCreateDatabase": true
  }
}
```

При SQLite цялата база е в един файл:

```bat
copy "pharmacy.db" "D:\Backup\pharmacy_%date%.db"
```

```bash
mysqldump -u root -p pharmacy_is > backup.sql
```
